# V8 测试与安全加固报告（2026-10-27）

## 本轮范围

以 GitHub V7（`44bcc7f`）为基线，不改原有主图 Skill、V2–V6 工作流和源商品结构，仅补强：

1. 星河 AI 返回图片的 HTTPS 下载验证（包含跳转地址）；
2. 下载文件大小 / base64 上限（12MB）；
3. 用文件真实内容确定 AI 图片扩展名，避免 JPEG 伪装 PNG；
4. 真实的离线贯通演练：Excel 导入 → 缺图预检查 → 生成 → 1440 像素质检 → 模拟审核 → SHA256 留档 → 审核 ZIP；
5. 添加独立尺寸图的手机端文字清晰度提示。

## 关键测试发现

- **已修复：外部图片 URL 无约束**。旧脚本使用 urllib 直接下载服务商返回的 URL，没有限制协议、内网地址、重定向和下载体积。新代码只允许常规 HTTPS 公网主机，检查跳转地址与解析 IP，不使用环境配置代理，并限制单图不超过 12MB。此校验属于纵深防御，不能声称完全防止 DNS 重绑定或代理/网络环境中的所有 SSRF 风险；联网部署仍需出站网络隔离。
- **已修复：图像文件名与真实格式可能不符**。生成 ZIP 现在根据图片实际格式选择 `.png` / `.jpg` / `.webp`。
- **发现实际排版风险：细字易缩小**。用脚本绘制的模拟拉手尺寸图合并后，`200 mm` 标注缩放得很小。现有自动质检只知道 1440×1440、JPEG 等事实，不能判断手机端可读性；V8 在含尺寸图批次增加显式警示并要求人工放大检查。无法据此承诺真实尺寸图也同样可读。
- **已验证：按预检查合格行生成、缺失尺寸图不串图**。一次批次中部分 SKU 缺图，其余可生成 SKU 正常输出。

## 实际执行的测试

- `python -m unittest discover -s tests -q`
- 仅使用程序绘制的**模拟工业拉手**和尺规标注，不是用户实物图，也不表示真实材质/孔距。
- 离线攻击路径模拟：`localhost`、内网/链路本地地址、非 HTTPS、用户信息 URL、恶意跳转、伪造超长返回、非法或超大 base64。
- 未联网调用星河服务：没有使用 API Key、没有产生第三方图片费用。

## 仍未验证

- 此环境未安装 Streamlit，因此**没有完成真实浏览器点击及移动端 UI 验收**。此前已经在代码层面完成流程和状态检测，但不应标为浏览器端通过。
- 未使用真实工业五金图片验证孔位、材质、尺寸/型号的一致性；上传真实图片后必须由运营和技术人员审核。
- 第三方返回域名 CDN / 签名 URL 的实时兼容性未做在线校验。严格的公网 HTTPS 限制可能拦截使用内网代理或特殊端口的服务商图片地址，需要安全评审后再考虑调整。
- GitHub Actions 的执行状态需在提交后核验；本报告记录离线测试，与线上部署无关。

## 交付建议

先选择一套真实产品（推荐拉手、锁具、阻尼转轴各一款），分别上传其原图、原尺寸图和确认过的 Excel 参数，在手机端逐字核对尺寸图。使用经过批准的图片进入待发布文件夹，不允许把“文件格式自动通过”直接称为“商品审核通过”。
